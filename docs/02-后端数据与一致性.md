# 后端、数据与一致性

## 分层与职责

| 位置 | 职责 |
| --- | --- |
| `api` | HTTP 参数、统一响应、异常映射、请求链路 |
| `config` | Spring Security 和环境配置 |
| `agent` | 意图与对话业务编排 |
| `state` | 持久化业务状态及事务边界 |
| `rag` | 切片、检索、缓存和知识持久化 |
| `llm` | Gemini HTTP 协议、超时、Token 与费用指标 |

Controller 不直接访问 Repository，LLM 不直接改变账单或创建工单。

## 数据模型

Flyway 是数据库结构的唯一来源：

- V1：`knowledge_chunk`；
- V2：`conversation`、`idempotency_record`、`pending_action`、`business_record`。

`conversation` 保存当前意图、状态和 slots；`idempotency_record` 保存同一请求的稳定响应；
`pending_action` 保存待确认操作；`business_record` 保存缴费或报修回执。

## 一致性设计

- 唯一约束 `(user_id, request_key)` 阻止重复幂等记录。
- `@Version` 在并发覆盖时触发乐观锁冲突，API 返回 409。
- `AgentService.handle` 和 `confirm` 使用事务。
- 确认 token 有用户归属、有效期和 consumed 状态。
- 幂等结果保留 24 小时；动作 5 分钟过期；定时任务每小时清理。
- Repository 查询用户归属，不能仅相信路径里的 conversationId。

## 异常策略

`GlobalExceptionHandler` 将校验错误、业务错误、依赖失败、并发冲突和未知错误映射到不同
HTTP 状态。响应不会包含 SQL、内部路径或堆栈；详细堆栈只进入服务端日志并由 `traceId`
关联。

## 阅读和调试建议

从 `AppController.message` 进入，跟到 `AgentService.handle`，再观察
`BusinessStateStore.reply/save/remember`。打开 H2 控制台并不是必要学习步骤；更推荐在测试中
使用 Repository 查询断言数据库状态，避免手工观察代替自动验证。
