# 业务范围与系统架构

## 业务目标

小赫兹是电力服务智能体个人作品，演示自然语言查账单、电费变化解释、电力知识问答、模拟缴费、停电报修和转人工。系统重点不是生成漂亮文本，而是演示“理解请求—校验权限—执行业务—返回证据—记录状态”的完整工程链路。

所有账单、缴费和报修均为合成数据，不接入真实支付或电网生产系统。

## 系统组成

```text
Vue 3 前端
  │ Bearer JWT / JSON
Spring Boot API
  ├─ Security：demo Token 或 Keycloak OIDC
  ├─ Agent：意图识别、对话状态、工具编排
  ├─ Decision：业务规则、统一决策、决策 Trace
  ├─ Domain：账单解释、缴费确认、报修确认
  ├─ RAG/LLM：知识检索、Gemini、模板降级
  └─ State：会话、幂等、动作、业务回执
       ├─ MySQL / H2
       ├─ Redis（知识回答缓存）
       └─ RocketMQ（知识索引完成事件）
```

项目采用模块化单体。当前规模下，事务、调试和部署收益高于拆分微服务；Redis 和 RocketMQ只用于确有意义的缓存及事件学习场景，不承担核心业务唯一事实来源。

## 核心流程

```text
用户发送消息
  → JWT/Token 校验
  → 会话所有者校验
  → clientRequestId 幂等查询
  → 意图识别
  → 确定性业务或 RAG/LLM
  → 事务保存会话和幂等响应
  → 返回 code/message/data/traceId
```

缴费和报修采用两阶段交互：先生成 5 分钟有效的确认 token，再由用户明确确认。确认事务会消费 token、创建业务回执并保存会话，防止刷新页面或重复点击造成重复执行。

## 业务规则与决策 Trace

当前已在后端增加轻量级 `BusinessRuleEngine`，先覆盖两个已有敏感场景：

- 模拟缴费：已缴账单命中 `PAYMENT_DUPLICATE_001` 并拒绝重复缴费；未缴账单命中确认类规则后进入用户确认。
- 停电报修：缺少地址时命中 `OUTAGE_ADDRESS_REQUIRED_001` 并继续收集信息；高风险报修命中 `OUTAGE_HIGH_RISK_CONFIRM_001` 并要求用户确认。

业务响应中的 `decisionTrace` 会返回本次决策的 `decisionId`、场景、决策类型、命中规则、规则版本、原因和执行结果，用于回答“系统为什么这么处理”。这一步对应升级方案中的 P0/P1；Replay、规则后台配置和业务指标看板仍作为后续演进。

## 明确边界

- 当前账单主数据是内置演示数据，不是完整账务模型。
- MySQL 保存对话和模拟业务状态，但不代表真实支付清算。
- Keycloak 是可替换的本地 OIDC Provider，不等于企业身份平台。
- Compose 是单机学习环境，不提供跨可用区高可用。
- LLM 输出不是事实来源；结构化账单、回执和权限判断由 Java 代码控制。
