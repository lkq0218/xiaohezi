# 生产化运行与恢复手册

## 能力边界

这是个人作品可负担的单区域部署基线：应用、MySQL、Redis、RocketMQ 与 Keycloak
由 Compose 编排。它能演示标准 OIDC、持久化、质量门禁、备份恢复和灰度流程，但不等于
跨可用区高可用生产平台。真实上线应使用托管数据库、托管身份服务、TLS、外部密钥管理
和独立监控平台。

## 首次启动

1. 复制 `.env.example` 为 `.env`，替换所有 `replace-with-...` 项。
2. 在 `infra` 目录执行 `docker compose up --build -d`。
3. 执行 `scripts/provision-keycloak.ps1`，通过环境变量创建演示用户，密码不进入 Git。
4. 打开 `http://localhost:8080`，浏览器使用 OIDC Authorization Code + PKCE 登录。
5. 检查 `/actuator/health/readiness`，确认数据库和应用就绪。

本地无 Docker 开发仍可使用 `APP_SECURITY_MODE=demo`；该模式只用于开发，不作为作品的
生产安全方案。

## 数据一致性与生命周期

- 会话、确认动作、幂等响应、缴费/工单回执均进入数据库。
- 会话和业务记录保留；用户只能读取绑定自己 subject/username 的资源。
- 确认动作有效期 5 分钟，成功消费后不可再次执行。
- 幂等响应有效期 24 小时，唯一键为 `(user_id, request_key)`。
- 每小时清理已过期幂等记录、已过期或已消费动作。
- `@Version` 检测并发覆盖，冲突返回 HTTP 409。

## AI 质量与告警

`backend/src/test/resources/rag-evaluation.csv` 是离线检索基准，当前门禁要求每条问题的
预期文档均进入 Top-1。新增知识或修改切片策略时必须同步扩展数据集，不能直接降低阈值。

Actuator 指标包括：

- `xiaohezi.llm.requests`：成功/失败调用数；
- `xiaohezi.llm.latency`：调用延迟；
- `xiaohezi.llm.tokens`：输入/输出 Token；
- `xiaohezi.llm.estimated.cost.usd`：依据配置单价估算的费用。

建议告警：5 分钟失败率 > 10%、P95 > 10 秒、每日估算费用超过个人预算，或 RAG CI
质量门禁失败。价格只是配置估算值，账单以模型供应商为准。

## 备份与恢复演练

备份：`scripts/backup-db.ps1`。脚本使用一致性快照并校验生成文件非空。

恢复必须在隔离环境先演练：

```powershell
scripts/restore-db.ps1 -BackupFile backups/xiaohezi-时间.sql -ConfirmRestore
```

恢复后检查 Flyway 历史、会话、业务回执和知识表记录数，再做登录、查询、确认回归。
生产恢复前必须停止写流量并另做当前库备份。

## 不可变发布、灰度与回滚

CI 使用 Git SHA 构建镜像，不复用 `latest`。先运行：

```powershell
scripts/deploy-canary.ps1 -Image registry/xiaohezi:<git-sha>
```

冒烟及指标观察通过后：

```powershell
scripts/promote-or-rollback.ps1 `
  -CandidateImage registry/xiaohezi:<git-sha> `
  -PreviousImage registry/xiaohezi:<previous-sha> -Promote
```

候选健康检查失败时脚本自动恢复上一镜像。数据库迁移必须保持向后兼容，已执行的 Flyway
文件不得修改；破坏性字段删除至少跨两个版本完成。
