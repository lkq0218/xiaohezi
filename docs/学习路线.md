# 学习路线

## 目标

学完后，你应能独立回答：一次消息怎样从浏览器到达 Agent、怎样读取和写入数据、怎样
避免重复执行、什么时候调用 LLM、为什么模型失败后系统仍能工作、用户为什么不能访问别人
的会话，以及怎样测试和部署这些能力。

## 第一阶段：先运行，再读代码

1. 安装 Java 21、Maven 3.9+、Node.js 20+。
2. 后端执行 `mvn test` 和 `mvn spring-boot:run`。
3. 前端执行 `npm ci`、`npm test`、`npm run dev`。
4. 使用 demo 模式完成登录、创建会话、查账单、知识问答、模拟缴费和报修。
5. 在日志中找到响应里的同一个 `traceId`。

掌握标准：不看文档也能启动两个进程，并能解释 400、401、403、409、500、503 的区别。

## 第二阶段：沿一次请求读代码

按以下调用链逐步打断点：

```text
App.vue
  → api.ts
  → SecurityConfig / RequestTraceFilter
  → AppController
  → AgentService
  → IntentResolver / RagService / BillExplanationService
  → BusinessStateStore
  → JPA Repository / MySQL
  → ApiResponse
```

建议练习：给消息请求增加一个无敏感信息的日志字段，并补测试证明它不会破坏响应。

## 第三阶段：掌握数据一致性

重点阅读 Flyway V2、四个 state 实体和 `BusinessStateStore`：

- 为什么幂等依赖数据库唯一约束，而不是只用 `if`；
- 为什么确认令牌要有过期时间和 consumed 状态；
- 为什么缴费确认必须使用事务；
- 为什么实体有 `@Version`；
- 服务重启后哪些状态能恢复，哪些演示账单主数据仍由代码初始化。

建议练习：补一个“两个线程同时确认同一 token，只有一个成功”的集成测试。

## 第四阶段：掌握认证与授权

先用 demo 模式理解 Bearer Token，再切换 OIDC：

- 浏览器执行 Authorization Code + PKCE；
- Keycloak 签发 JWT；
- 后端校验 issuer、签名和有效期；
- realm role 转为 `ROLE_USER` / `ROLE_ADMIN`；
- 服务层再次校验资源所有者。

掌握标准：能解释“认证成功”为什么不等于“可以访问任意 conversationId”。

## 第五阶段：掌握 Agent 与 RAG

按顺序学习规则意图、LLM 意图、确定性工具、RAG 检索、生成回答和降级模板。运行
`RagOfflineEvaluationTest`，修改一个问题观察质量门禁怎样失败。

掌握标准：能区分“模型生成的内容”“数据库事实”“知识库证据”和“业务执行结果”。

## 第六阶段：掌握交付

阅读 CI、Dockerfile、Compose 和 `scripts`：

- CI 为什么使用 clean install 和不可变 Git SHA 镜像；
- 健康检查和业务接口为什么不是一回事；
- 备份为什么要实际恢复验证；
- Flyway 为什么不能修改已执行迁移；
- 候选版本失败后怎样回到上一镜像。

最终练习：在有 Docker 的环境按运行手册完成一次启动、OIDC 登录、备份、隔离恢复、候选
部署和回滚，并记录命令、结果和问题。

## 第七阶段：从文本 Agent 扩展到多模态

完成前六阶段后再阅读 [多模态能力设计](06-多模态能力设计.md)，按 M0～M7 顺序实践。
不要同时开发全部模态，先完成“账单图片 → 字段提取 → Java 校验 → 用户纠错 → 解释”的闭环。

学习时始终区分三类能力：

- 图片理解：OCR、VLM、结构化输出和视觉问答；
- 跨模态检索：OCR/说明文字基线、图文共享向量、融合召回和证据区域；
- 图片生成：VAE、扩散模型、DiT、Flow Matching 和 ControlNet，只进入隔离的创作链路。

掌握标准：能说明模型为什么不能计算最终账单金额、图片提示词注入怎样被隔离、生成图片
为什么不能成为证据，并能用冻结评测报告证明至少一项多模态能力达到预设门禁。
