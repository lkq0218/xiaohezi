# Agent、LLM 与 RAG

## 混合智能体

系统不是让 LLM 直接决定一切，而是组合三类能力：

1. 规则或 LLM 意图识别；
2. Java 确定性业务工具；
3. RAG + LLM 知识回答。

账单金额计算、权限、幂等、确认和回执必须确定；自然语言分类与知识组织可以使用模型。

## 意图与状态

`IntentResolver` 返回意图、置信度、来源和 Token 数。`AgentService` 根据意图进入账单查询、
账单解释、缴费、知识问答、报修、转人工等分支。Conversation 的 `state` 和 `slots` 支持
补充地址、等待确认和完成状态。

## RAG 链路

```text
Markdown 知识
  → 按标题与长度切片
  → 可选 Gemini Embedding
  → 向量排名 + 中文二元词关键词排名
  → RRF 融合
  → Top-K 上下文
  → Gemini 受约束回答
```

向量服务不可用时降级为本地关键词检索；LLM 不可用时降级为安全模板。引用来自实际命中的
知识块，系统提示词要求资料不足时明确说明，不允许补造政策数字。

## 缓存和事件

Redis 缓存知识回答 30 分钟，失败只影响性能，不影响主流程。知识块持久化完成后可向
RocketMQ 发布事件；消息失败不会让内存检索失效。它们都是可降级设施，不是缴费或工单的
事实来源。

## 质量评估

`rag-evaluation.csv` 保存问题与预期文档，`RagOfflineEvaluationTest` 要求当前样本 Top-1
命中。修改知识、切片或排序后应增加真实失败样本，而不是为了通过 CI 随意降低门槛。

LLM 指标记录成功/失败、延迟、Token 和估算费用。估算单价来自配置，真实费用以供应商
账单为准。
