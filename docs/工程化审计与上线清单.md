# 工程化审计与上线清单

## 结论

项目已经具备清晰的前后端分层、RAG/Agent 设计文档、外部调用超时与降级、部分单元测试和中间件学习实现，但此前仍偏“可演示”，不完全满足可部署、可排查和安全配置要求。本轮补齐了统一异常、参数校验、请求链路、健康指标、数据库迁移、容器部署和接口回归测试。

## 范围与边界

- 当前用户：学习与演示环境中的电力客户。
- 核心闭环：登录、创建会话、咨询或发起模拟业务、二次确认、获得结构化结果。
- 当前不包含：企业身份租户、真实扣款、真实工单、跨区域高可用部署。
- 成功标准：后端和前端可构建；自动化测试通过；错误使用正确 HTTP 状态码并返回
  统一结构；请求可通过 `traceId` 定位；容器健康检查可判断服务状态。

## 已完成项

| 领域 | 落地内容 | 验证方式 |
| --- | --- | --- |
| 输入 | 登录、消息、确认请求使用 Bean Validation | 空值及超长请求返回 400 |
| 异常 | 全局区分参数、业务、依赖、未知异常 | 响应不包含堆栈与内部路径 |
| 安全 | demo/OIDC 双模式、角色和资源所有者校验 | 匿名 401、越权 403、OIDC JWT 校验 |
| 可观测 | 请求 ID、耗时、状态日志；Actuator 健康和指标 | 检查响应头、响应体和控制台日志 |
| 数据 | Flyway V1/V2、事务、幂等、TTL、乐观锁 | 空库迁移及数据集成测试 |
| 部署 | 非 root 多阶段镜像与 Compose 健康依赖 | `docker compose up --build` |
| 测试 | 后端接口/安全集成测试，前端 API 单元测试 | `mvn test`、`npm test` |

## 本轮生产化补齐

- 进程内会话、幂等响应、确认动作已迁移数据库，并增加唯一约束、TTL 清理和乐观锁。
- 增加 Keycloak/OIDC JWT 模式、Authorization Code + PKCE 前端登录、USER/ADMIN 角色及资源所有者校验。
- 增加 RAG 离线评估数据集、Top-1 质量门禁、LLM 延迟/Token/估算费用指标和故障测试。
- 增加 GitHub Actions 测试、构建、文件系统及镜像漏洞扫描和 Dependabot。
- 增加备份恢复、不可变镜像、候选环境、健康检查与自动回滚脚本。

## 仍需外部环境完成

以下内容不能用少量基础设施代码伪装为“已完成”：

1. 在真实 GitHub 仓库启用 Actions、Dependabot 和分支保护，并处理扫描发现项。
2. 在真实服务器接入 HTTPS、镜像仓库、监控通知渠道和外部密钥管理。
3. 用长期运行数据校准 SLO、LLM 费用阈值和告警阈值。
4. 在独立环境实际执行备份恢复和灰度演练并留存记录。
5. 若面向真实用户，用企业/云 IdP 替换本地 Keycloak，并完成隐私与合规评审。

## 上线前检查

- [ ] 核心正常、异常、重复确认和越权用例全部通过。
- [ ] 所有生产密钥来自密钥管理或受保护环境变量。
- [ ] `.env`、日志、构建产物中不存在真实 Token、密码或用户敏感信息。
- [ ] Flyway 在生产副本验证，数据库已备份且恢复演练成功。
- [ ] 健康检查、错误率、P95 延迟、线程/连接池和外部依赖告警可用。
- [ ] 已记录当前镜像版本、上一稳定版本、负责人和回滚命令。
- [ ] 多实例部署前确认账单主数据也已替换为真实外部数据源。
